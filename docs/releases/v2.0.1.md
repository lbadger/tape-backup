# v2.0.1 — Restore fixes and clearer status output

This patch fixes three issues found in the post-release review and makes tape
progress and information easier to read in a terminal.

- **Prevent competing restores across home directories.** File and native ZFS
  restores use a shared destination lock under `/run/lock`. Jobs using different
  home directories or media cannot restore to the same destination path at once.
  Tar restores also recheck recorded history immediately before an incremental
  apply, preventing a changed baseline from being silently accepted.
- **Avoid rereading an exhausted cartridge.** Multi-volume verify, list, and
  restore operations request the continuation tape directly. They no longer
  rewind and search the previous cartridge before prompting. Appended backups
  on a shared cartridge still reuse that cartridge.
- **Make inventory exclusions agree with GNU tar.** Backslash escapes, POSIX
  character classes, bracket patterns, and literal patterns now use matching
  behavior consistent with the archive, including the source locale. Existing
  exclusion policies retain their archive-selection behavior.
- **Improve terminal progress.** Wrapped rows separate read/delivered/committed
  totals, buffer occupancy, source rate, I/O rate, elapsed time, and ETA. The
  final tape commit and metadata write show `finalizing` instead of suggesting
  the operation is already finished.
- **Make information commands readable.** `status`, `doctor`, `inspect`, and
  `verify` show labeled details in a terminal. `info` is an alias for `inspect`.
  `--json` forces JSON and `--text` forces readable output. Redirected stdout
  still defaults to JSON, and redirected progress retains compact log lines.

```bash
./tape-backup status
./tape-backup info --first
./tape-backup inspect --json > cartridge.json
./tape-backup status --text | less
```

The tape formats and SSH transport remain compatible with v2.0.0. Update the
source-side executable too when using exclusions over SSH. The Linux x86-64
binary bundles Python and targets glibc 2.31 or newer; use the attached checksum
to verify the download.

Validation includes source and standalone executable tests, real GNU tar and
SSH, independent-process restore locking, simulated multi-cartridge reads,
terminal/JSON output, a no-Python Debian 11 smoke test, and the GitHub OpenZFS
scratch-pool tests. Physical tape hardware was not available for this validation.

See the [README](https://github.com/lbadger/tape-backup/blob/v2.0.1/README.md)
for usage and the [roadmap](https://github.com/lbadger/tape-backup/blob/v2.0.1/docs/project-review-and-roadmap.md)
for later feature work.
