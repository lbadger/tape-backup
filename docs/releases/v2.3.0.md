# v2.3.0 — Tape ETAs, automatic eject, and streaming diagnostics

- **Plan tape changes while running.** Tar and ZFS backups/restores show estimated
  cartridge counts, current-tape ETA, and total-job ETA alongside archive progress.
  Estimates use supported drive capacity attributes, observed tape lengths,
  inventory hints, and verified archive sizes. Media-change waits are excluded
  from ETA rates. Unknown future archive sizes remain explicitly unknown.
- **Override estimated capacity.** `--cartridge-capacity 2300GiB` now works for
  live backup and restore as well as previews. It affects estimates only and does
  not limit writes or force tape changes. Drive capacity detection is read-only
  and occurs when opening a volume, before streaming writes.
- **Automatically unload full backup tapes.** Full and incremental backups rewind
  and eject the exhausted cartridge before requesting the next tape, including
  configured test size limits. An eject failure preserves buffered data and allows
  retry at the prompt. The final cartridge stays loaded; restore tape changes
  retain their existing manual/loader behavior.
- **Diagnose uneven streaming.** Progress reports cumulative source-wait, flush,
  and position-query time plus recovery-buffer flush counts. Routine durability
  queries occur every 64 MiB instead of 16 MiB, retaining the mandatory check and
  synchronous fallback before recovery space runs out. This reduces routine
  query traffic; actual throughput improvements depend on the drive and source.

Tape formats 3/4 and SSH protocol 3 are unchanged. Existing backups remain readable.
Compression, replay, partial cartridges, and unknown restore-chain sizes can affect
estimates; reaching an estimate never indicates successful completion.

The Linux x86-64 executable embeds Python and requires glibc 2.31 or newer.
Download `tape-backup` and `tape-backup.sha256`, then verify with
`sha256sum --check tape-backup.sha256`. An already-running backup continues using
its loaded version; use the new executable for subsequent runs.

See the [README](https://github.com/lbadger/tape-backup/blob/v2.3.0/README.md) for
progress examples, streaming diagnostics, and command options.
