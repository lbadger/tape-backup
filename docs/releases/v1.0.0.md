# v1.0.0 — Continuous tape streaming

This major update removes routine per-chunk tape flushes. A background reader
feeds small frames to the writer continuously, while a bounded recovery window
retains data until the drive confirms it has reached the tape.

## Changes

- Stream local or SSH sources through frames of up to 4 MiB; writing starts
  without waiting for the entire RAM buffer to fill.
- Use non-flushing SCSI READ POSITION reports to confirm writes. Commit at volume
  boundaries and backup completion, with a safe synchronous fallback when
  recovery space fills or position reporting is unavailable.
- Recover multiple unconfirmed frames after end-of-medium or write errors, and
  validate and suppress duplicate frames during restore.
- Increase the default buffer budget to 1 GiB and maximum to 10 GiB. Read-ahead
  and recovery each have that budget; allow more than twice the selected size in
  available RAM, including process and snapshot overhead.
- Show queue usage, retained recovery bytes, confirmed tape bytes, live source
  speed, reader state, and flush reasons in status output.
- Fix manual tape-change prompts on non-seekable terminals.

## Upgrade and compatibility

New backups use **tape format 3** and require v1.0.0 for restore, verify, inspect,
and incremental-base loading. Existing format-2 tapes from v0.2/v0.3 and earlier
development builds remain readable, and incremental chains can cross versions.
Format-3 metadata scans read past archive records because per-chunk filemarks
have been removed.

Upgrade both machines for SSH backups: the transport now uses 64-bit version-2
packet framing. Existing backup commands continue to work. Tape changes, slow
sources, and recovery-buffer fallback commits can still cause pauses.

The standalone executable targets **Linux x86-64 with glibc 2.31 or newer**.
Python is bundled; GNU tar and `mt` from `mt-st` are still required for physical
tape operation. Download `tape-backup` and `tape-backup.sha256`, then run:

```bash
sha256sum --check tape-backup.sha256
chmod +x tape-backup
./tape-backup --version
```

## Validation

77 automated tests pass, including local and SSH full/incremental restores,
simulated delayed write failures and multi-frame replay, legacy-format
compatibility, and a 10 GiB standalone backup/verify/restore round trip. The
standalone executable also passes a Debian 11 smoke test without Python installed.
Automated tape-failure tests use simulated media; qualify recovery and restore on
your own drive and loader.

[streaming design](https://github.com/lbadger/tape-backup/blob/v1.0.0/docs/continuous-streaming.md)
for operation and recovery details.
