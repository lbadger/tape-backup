# v2.2.0 — Cartridge inventory, restore plans, and backup previews

- **Label cartridges.** New tapes carry a recording ID and readable label.
  `--label-prefix BOOKS` labels new cartridges `BOOKS-001`, `BOOKS-002`, etc.
  Appends retain existing labels. Older tapes remain readable and appendable.
- **Keep an optional inventory.** `backup` and `zfs-backup --inventory FILE`
  record every cartridge after commit. `inventory --output FILE` rebuilds or
  extends observations from loaded tapes. Catalog/first-header reads are the
  default; `--scan` explicitly permits archive traversal. Cache write failures
  warn without undoing a committed backup. The cache is never required to restore.
- **Plan recovery.** `restore --to ID --plan --inventory FILE` shows the full
  chain, cartridge labels, and unresolved backup/volume information without a tape
  drive or destination. Omit `--plan` to restore a complete discovered chain.
  `zfs-restore` supports the same options. Actual streams are always revalidated.
- **Preview backups.** `backup --dry-run` and `zfs-backup --dry-run` validate the
  source and estimate size without archive streaming or tape writes, locally or
  over SSH. `--cartridge-capacity` supplies an approximate cartridge-count input.
  A full preview needs no drive; incremental previews read their parent's header.

Inventory and plan information is advisory, not archive verification. Earlier
tapes without a usable catalog may require an explicit scan for complete
observations. Readable label prefixes restart numbering for each command; recording
IDs distinguish duplicates. Wipe/reuse starts a new identity. Preview estimates do
not certify blank media, append readiness, or remaining capacity.

Tape formats 3/4 and SSH protocol 3 are unchanged. New labels are optional header
fields; existing archives remain readable. Explicit-ID and stepwise restores
remain supported. No mandatory disk archive or restore catalog is introduced.

Validation covers multi-cartridge simulations, legacy identity compatibility,
atomic inventories, missing/conflicting/stale observations, actual GNU tar and SSH,
source and standalone binaries, Debian 11 without Python, and native OpenZFS
full/incremental/raw restores in CI. Physical tape qualification remains separate.

The Linux x86-64 executable includes Python and requires glibc 2.31 or newer.
See the [README](https://github.com/lbadger/tape-backup/blob/v2.2.0/README.md) for
commands, limits, and examples.
