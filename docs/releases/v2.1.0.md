# v2.1.0 — Wipe at tape changes and overall progress

Backups can now initialize a used spare cartridge at the load prompt without
ending the backup or discarding buffered data. Backup and restore also show
overall progress across tape changes and requested archive chains.

At a blank-cartridge prompt, type `wipe`, check the loaded cartridge, then type
`WIPE` at the separate destructive confirmation. The backup requests a short
erase, verifies that the tape is blank, and continues with the same volume number.
Canceling the erase or encountering an erase error returns to the cartridge
prompt. Pressing Enter alone still requires blank media.

The prompt protects headers identifying the active backup or its base and
remembers the first-header fingerprints of cartridges already used by this job,
including the cartridge selected for appending. It rechecks the header after
confirmation and refuses unreadable or corrupt recognized headers. Unrelated
backups on the spare are destroyed only after explicit confirmation. Read and
append-selection prompts do not offer erasure; automated loaders must continue
to supply blank media. Separate commands remain blocked by the active drive lock.

Terminal progress now includes a total bar. Backup uses estimated source size;
a fresh tar restore chain estimates progress by archive without extra tape
scans. In-place incremental and native ZFS restores include their verification
pass, then use exact verified archive sizes during application. Estimates and
unknown totals are labeled. Progress remains below 100% until the operation
successfully completes, including final flushing. Redirected logs show a total
percentage and preserve machine-readable stdout.

This update cannot change an already-running backup process. Keep that process
alive if its buffered continuation data is still needed; replacing its executable
does not give the existing prompt new commands.

The tape formats and SSH protocol remain compatible with v2.0.x. The attached
Linux x86-64 executable bundles Python and requires glibc 2.31 or newer.

Validation covers simulated multi-cartridge backup/verify/restore with reused
spares, earlier-volume and append-base protection, confirmation and erase errors,
shared drive locking, prompt logging, progress accounting, real GNU tar/SSH,
standalone terminal output, a Debian 11 no-Python smoke test, and native OpenZFS
scratch-pool tests in CI. Physical tape hardware was not available.

See the [README](https://github.com/lbadger/tape-backup/blob/v2.1.0/README.md)
for instructions and progress semantics.
